# M14 image-decision data protocol

## Current state

The initial M14 pilot is Oxford Flowers-102, restricted to internal non-commercial training under the user's explicit confirmation on 2026-10-07. This is a narrow 4-choice flower-identification pilot, not a broad multimodal System-One benchmark. The source's public page does not publish a general image license; no public license is claimed here, and the source is not to be redistributed. The permission attestation and scope are recorded in `data/manifests/manifest.json`.

## Required normalized record

One JSONL row represents one decision question:

```json
{
  "id": "stable-question-id",
  "source": "dataset/version",
  "source_family": "source/task-family",
  "group_id": "image-video-episode-group",
  "images": ["relative/path/image.jpg"],
  "state": {"key": "value"},
  "question": "Which action should be taken?",
  "type": "choice",
  "candidates": [{"id": "c1", "text": "..."}, {"id": "c2", "text": "..."}],
  "target": "c1"
}
```

Candidate IDs are metadata and must not be serialized into model text unless the ID itself is semantically meaningful. The trainer must group candidate scores by question before CE/Brier loss. Image references must resolve inside an immutable local source store; do not rewrite upstream images in place.

## Split and source manifest requirements

For every source, record dataset/version, source URL and immutable revision, source and image licenses/terms separately, redistribution and commercial-use constraints, transformation version, source checksum, and attribution. Record image provenance when source terms require it.

Freeze train, model-validation, calibration, and test IDs with image/group-disjoint partitions. In-domain source families may occur in each partition; if an OOD split is defined, its families must be absent from every in-domain split. Deduplicate images by exact hash and perceptual hash; check normalized text and source groups for leakage. Keep benchmark test data out of model selection. OOD is optional for a single-family pilot.

The trainer may consume train and model-validation only. The temperature fitter may consume calibration only. Test and OOD partitions are evaluation-only.

## Readiness gate

`data/manifests/manifest.json` records source details, permission scope, split counts and hashes, and the passed leakage report before training is launched. The proposed 100K–300K scale is a future target, not a requirement for a first controlled run.

## Files and launch protocol

Store images under `data/images/` and normalized JSONL files under `data/processed/`:

```text
data/processed/train.jsonl
data/processed/model_validation.jsonl
data/processed/calibration.jsonl
data/processed/test.jsonl
data/processed/ood.jsonl  # optional
data/manifests/manifest.json
data/manifests/leakage_audit.json   # generated by validate_data.py
```

VKong setup downloads the pinned `Donghyun99/Oxford-Flower-102` mirror revision
`7e43fe37eeb9278138ab0bd2d0abb10d0f703d09` directly to the rental disk, then
recovers only images listed in the passed leakage audit. Each recovered image
must match its recorded SHA-256 before the workload proceeds. The image archive
is not uploaded as VKong source and is not exported from the rental.

Each split entry in the manifest records its relative path, row count, and SHA-256. Every source entry must state an immutable revision, source and terms URLs, license identifier, source payload SHA-256, and explicit `terms_verified` / `image_rights_verified` attestations. Only set those attestations after reviewing the actual image-use terms; code cannot determine rights automatically. The global manifest checks for verified terms, recorded provenance, and the test-exclusion policy must also be true. Leakage and split checks are computed from the files rather than trusted from hand-edited booleans.

Run the full audit before launch:

```bash
.venv/bin/python retrain/14_vlm_systemone_4b/scripts/validate_data.py
```

It verifies schema, split hashes/counts, unique source IDs, group separation, OOD-family separation when OOD is present, long-text duplicates, exact image hashes, and near-duplicate image hashes. A passing run writes a leakage audit bound to the exact manifest and split hashes. Training checks that audit and rehashes the recorded image corpus, then opens only `train.jsonl` and `model_validation.jsonl`; it never loads calibration, test, or OOD labels. Prediction takes one explicitly named split. Use model validation for checkpoint selection, calibration only for fitting temperature, and test/OOD only for final reporting.

The first implemented arm is V1: a fresh linear head over the pinned, frozen multimodal backbone. It scores candidates one at a time to bound peak activation memory, groups their scores by question for CE+Brier loss, rejects overlong sequences instead of truncating them, and defaults to a 786,432-pixel cap. Training emits one JSON progress event per optimizer step, including loss, throughput, ETA, and peak VRAM; `last.pt` is resumable and `best.pt` is selected only on `model_validation`. These are local implementation settings and should be versioned if changed.
